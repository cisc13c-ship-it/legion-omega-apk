# Contributing

1. Open an issue describing the problem, expected behavior and evidence.
2. Work in a feature branch; do not rewrite canonical history.
3. Keep changes small and independently reviewable (WIP=1).
4. Include tests and update documentation for every behavior change.
5. Do not add binaries or vendored dependencies without explicit review.
6. Include SPDX license identifiers in new source files.
7. Add dependencies only after license, provenance, maintenance and security review.
8. Never commit credentials, signing keys, tokens, device data or private logs.
9. AI-assisted changes require human review and test output.
10. A skill is not enabled merely because it was generated; it must pass schema, policy, sandbox and functional tests.

Separate verified facts, inference and unknowns. Never claim a build or device test passed without logs and reproducible evidence.
